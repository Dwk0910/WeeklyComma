# 마음의 양식의 쉼터, 주간쉼표에 오신 여러분들을 환영합니다.

### 개요
주간쉼표는 여러분들의 도서 추천 경험을 향상시키기 위해 개발된 웹 애플리케이션입니다.
도서를 읽으며 마음의 평안을 되찾거나, 혹은 점차 전개되는 이야기를 보며 재미를 찾고 싶어 떠나 보아도, 정작 마음에 드는 도서를 찾지 못해
골머리를 앓거나 실망하신 경우가 한 번쯤 있었으리라 생각합니다. 주간쉼표는 이 문제를 해결하기 위해 세상에 나오게 되었습니다.
***
### 주요 기능
해당 웹 애플리케이션에서는 여러분들의 취향에 걸맞는 도서를 장르나 길이 등 표지를 보는 것만으로도 알 수 있는 정보뿐만이 아닌,
줄거리와 소재, 작가가 전하고 싶은 의미 등 내적 요소들까지 고려하여 추천해줄 수 있습니다. 또한 이 과정은 전부 책을 전부 읽고
평가를 내리는 평론가들에 의해 이루어지기 때문에, 타 도서 추천 사이트보다 책의 소개 및 개요문에서 더 큰 흥미를 이끌어낼 수 있습니다.
만일 추천에도 불구하고 정말 원하는 책을 찾지 못했다면, 평론가들에게 원하시는 책에 대한 정보에 대해 공유해주십시오. 최선을 다 해 도와드리겠습니다.

### 주간 추천 및 이력
추천글은 작성 주차와 관계없이 이주의 도서에 연결하거나 수정할 수 있습니다. 게시글의 `Attribution`은 연결된 책의 ISBN(`bookId`)만 보관합니다.

현재 선정은 `adminsettings`의 `recommend_isbn_{low,mid,high}`, `recommend_post_{low,mid,high}`, `mainPick`에 저장합니다. 선정 주차는 게시글과 별도로 `recommendationWeekStart`에 해당 주차의 시작 날짜를 저장하여 추적합니다. 주차는 한국 시간 기준 매월 1~7일, 8~14일, 15~21일, 22~28일, 29일~말일로 구분합니다.

주차가 바뀌면 실제로 선정된 코스별 ISBN·추천글 ID·선정 연도/월/주차·코스를 `recommendation_history`에 저장하고 현재 추천 설정을 비웁니다. 배너 설정과 원본 도서·게시글은 유지합니다. 새 선정은 도서와 해당 도서의 추천글을 반드시 함께 선택해야 합니다. 기존의 추천글 없는 선정 이력은 그대로 보존합니다. 동일한 책과 추천글을 다른 주차에 다시 선정할 수 있습니다. 이력 저장과 설정 초기화, 주차 갱신은 하나의 트랜잭션으로 처리합니다.

만료 처리는 매일 한국 시간 자정, 서버 시작 시, 설정 조회·변경 시 확인합니다. 서버가 여러 주 동안 중지되어도 저장된 선정 주차로 한 번만 이력을 기록합니다. 이 기능을 처음 실행하여 `recommendationWeekStart`가 없을 때는 기존 설정을 현재 주차의 선정으로 간주합니다. 기존 SQLite 이력 테이블에 추천글 ID의 유일성 제약이 있으면 시작 시 데이터를 보존하면서 해제합니다.

추천 설정은 `PUT /adminsettings/recommendations`로 모든 코스의 도서·추천글과 대표 코스를 한 번에 저장합니다. 예: `{"selections":[{"course":"high","isbn":"선정 ISBN","postId":101}],"mainPick":"high"}`. 빈 `selections`와 `mainPick: null`로 전체 선정을 해제할 수 있습니다. 개별 추천 키의 PUT/DELETE는 허용하지 않으며, 서버에서 도서 존재 여부, 코스 난이도, 추천글 유형과 연결 ISBN을 검증합니다. 선정된 도서나 추천글이 삭제되면 연결된 선정 쌍도 함께 해제됩니다.

관리자는 `GET /recommendation-history?limit=12`로 현재 선정과 지난 이력을 최신순으로 조회할 수 있습니다. `isbn` 또는 `course=low|mid|high`로 필터링할 수 있으며, 최대 50개까지 조회합니다. 교체 팝업은 도서와 추천글을 함께 선택하며 최근 선정 목록을 제공합니다. 추천 책 관리에서는 최근 선정 도서를 열 수 있고, 개별 도서 화면에서는 해당 책의 선정 이력을 확인할 수 있습니다.

### Star와 과거 인기 추천
로그인한 사용자는 `PUT /books/{isbn}/star`로 책에 Star를 등록하고 `DELETE /books/{isbn}/star`로 취소할 수 있습니다. 사용자·도서 조합을 기본 키로 저장하므로 반복 요청이나 동시 요청도 한 표로 집계합니다. 쓰기 요청에는 기존 로그인 쿠키와 CSRF 헤더가 필요하며, `GET /books/{isbn}/star`는 비로그인 상태에서도 집계 수를 조회할 수 있습니다. 로그인 쿠키가 유효하면 본인의 등록 여부도 반환합니다.

`GET /books/popular`는 과거 선정 이력이 있고 Star가 **10개를 초과한** 책을 Star 수 내림차순으로 반환합니다. 동률이면 ISBN 오름차순이며, 여러 주에 선정된 책도 한 번만 표시합니다. 기본 조회 수는 기존 메인 레이아웃에 맞춘 6권입니다(`limit=1~50`). 이주의 책과 인기 도서의 Star 버튼을 통해 등록·취소할 수 있으며, 11개에서 10개로 줄면 인기 목록에서 제외됩니다. 서버에 저장한 커스텀 표지는 `ServerImg`, 외부 기본 표지는 이미지 URL을 사용합니다. 도서 또는 사용자를 삭제하면 해당 Star도 정리합니다.

### 공지
`/notices`에서 공개 공지 목록을 10개씩 조회합니다. 고정 공지를 먼저 표시하고, 각 그룹 안에서는 작성일과 실제 글 ID 내림차순으로 정렬합니다. 고정 공지도 실제 글 번호를 표시합니다. 목록 페이지는 `?page=2`처럼 URL에 유지되며 상세 화면의 목록 버튼으로 돌아와도 유지됩니다.

`/notices/{id}`는 공지 본문과 작성자·등록일·수정일을 표시합니다. 본문은 작성 에디터와 같은 서식으로 읽기 전용 표시하며, 이전·다음 공지는 고정 여부와 관계없이 작성일순으로 연결합니다. 상단 공지 메뉴·확성기·메인의 최신 공지를 통해 접근할 수 있습니다. `GET /posts/latestnotice`는 작성일과 ID를 기준으로 최신 공지 한 건을 반환합니다.


소개·공지·이벤트·관리 메뉴는 현재 경로에 따라 같은 밑줄 표시를 사용하며, 상세 화면에서도 해당 게시판 메뉴가 활성화됩니다. 등록되지 않은 주소와 존재하지 않는 글 ID, 잘못된 글 ID, 게시판 유형과 맞지 않는 글의 상세 주소는 공통 `/404` 화면으로 이동합니다. 잘못된 주소는 브라우저 이력에 남기지 않으며, 공통 화면에서 이전 페이지로 돌아가거나 홈으로 이동할 수 있습니다. 통신 오류는 404로 처리하지 않고 기존 재시도 안내를 표시합니다.


### 이벤트
`/events`와 `/events/{id}`는 공지와 동일한 목록·상세 화면을 사용하고 `EVENT` 유형의 글만 표시합니다. 관리자 이벤트 게시판에서 작성한 글과 고정 상태가 공개 화면에 반영됩니다. 실제 글 번호, 10개 단위 페이지 이동, 본문 서식, 작성 정보, 이전·다음 글, 원래 목록 페이지로 복귀하는 동작을 공지와 공유합니다.
